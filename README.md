# Путь стажёра (AI-buddy)

Hack&Change 2026, трек Авито. ИИ-помощник стажёра: отвечает по документам команды с источником, наводит на решение вместо «сделай за меня»,
готовит заявки на доступ (отправляет человек), замечает расхождения в инструкциях, ведёт к людям и помогает собрать журнал достижений.
**Чаты стажёра технически недоступны наставнику, лиду и HR.**

> Тестовые данные, не регламенты Авито. Все сотрудники, документы и сервисы вымышленные.

## Запуск одной командой

```bash
cp .env.example .env
docker compose up --build
```

* API: http://localhost:8000/api · OpenAPI: http://localhost:8000/docs · справочник ручек: [API.md](API.md)
* Поднимаются `db` (PostgreSQL 16), `redis`, `mock-corp` (MCP-имитация Jira/Confluence/Bitbucket/Mattermost/заявочной системы), `api`.
* При первом старте применяются миграции и загружается сид. GPU не нужен.

Тестовые логины (без пароля): `POST /api/auth/login {"user_id": "anya"}` — `anya` (стажёр, основной сценарий), `dima` (стажёр, первая неделя),
`boris` (наставник), `maria` (лид).

## Подключение ключа

| Переменная | Значение |
|---|---|
| `LLM_PROVIDER` | `fake` — без ключа, детерминированные ответы; `openai_compatible` — любой OpenAI-совместимый API |
| `LLM_BASE_URL` | Например, `https://api.openai.com/v1` или внутренний шлюз |
| `LLM_API_KEY` | Ключ провайдера (в репозиторий не коммитится, только в `.env`) |
| `LLM_MODEL` | Модель для ответов (chat completions) |
| `EMBEDDINGS_MODEL` | Модель эмбеддингов (`/embeddings`) |

Проверка подключения: `make check-llm` (или `docker compose exec api python -m app.cli check-llm`).
Без ключа оставьте `LLM_PROVIDER=fake`: все сценарии S1–S5 и J проходят на детерминированных ответах.
При смене провайдера эмбеддингов переиндексируйте вики: `docker compose exec api python -m app.cli reindex`.

## Порядок проверки сценариев (через /docs или фронтенд)

1. **«Сделай за меня»**: `anya` → новый чат в задаче «Платёжный модуль» → «Сделай за меня задачу» → два наводящих шага, затем прямой ответ и человек.
2. **S1 кто отвечает**: «Кто отвечает за сервис платежей?» → карточка Игоря Л. с цепочкой → `POST /contacts`.
3. **Права**: «Покажи условия оценки стажёров» → «В доступных мне материалах этого нет» (документ лида не раскрывается).
4. **S3 заявка**: «Мне нужен доступ к Jira-проекту PAY» → `POST /actions/{id}/confirm` → `POST /dev/access/approve` → уведомление и шаг чек-листа.
   Затем «Дай доступ к общему глобальному пространству» → отказ без заявки.
5. **S4 расхождение**: «Как получить доступ к тестовому стенду?» → два варианта → подтвердить сообщение владельцу → замечание видно наставнику.
6. **J журнал**: `POST /journal/suggest` → `POST /journal` → удалить чат → запись осталась → `POST /journal/draft` → `POST /journal/export` (PDF).
7. **Приватность и наставник**: `GET /privacy`; под `boris` — `GET /mentor/interns` (прогресс есть) и `GET /chats/{id}/messages` → 403.

## Разработка и тесты

```bash
cd apps/api
python -m pip install -e ".[dev]"
python -m pytest -q --cov=app --cov-fail-under=80   # make coverage
python -m ruff check app tests                       # make lint
PYTHONPATH=../../mcp/mock-corp python -m app.cli eval  # make eval: 40+ вопросов, точность роутера, утечки, инъекции
```

Тесты идут на SQLite в памяти и `mock-corp` в процессе; в CI (GitHub Actions) — ещё и на PostgreSQL. Порог покрытия 80% (`--cov-fail-under`),
отчёт `coverage.xml` сохраняется артефактом.

## Архитектура ответа

`сообщение → правила (действия, безопасность) → LLM-роутер (JSON) → обработчик маршрута → SSE`.
RAG: чанки по заголовкам, права доступа применяются в SQL **до** поиска, гибридное ранжирование (лексика + вектор, RRF), порог уверенности,
детектор расхождений по теме документа. Документы и вложения — недоверенные данные: фрагменты с инструкциями для модели отбрасываются.
Заявки создаются только через `POST /actions/{id}/confirm` — у ассистента нет инструментов с побочными эффектами.

Честные границы прототипа: эмбеддинги хранятся в JSON и ранжируются в Python (корпус маленький); перенос на pgvector — замена функции
`search()`. Фронтенд в этом репозитории пока не собран — интерфейс описан в [API.md](API.md).
